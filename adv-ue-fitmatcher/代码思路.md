# ADV × UE 对接工具 · 代码思路（v3.0）

> 读法：先看第 0、1 节，知道这工具到底在替你做哪几步手工活；
> 想看图，打开同目录的 `思维导图.html`；
> 想动手，直接跳到第 7、8 节。

---

## 0. 一句话

**你手工要做的事**：在 ADV 里补齐 UE 有的骨 → Build → 把 UE 骨搬到 ADV 的骨上 → 把它们绑在一起。
**工具做的事**：把这几步变成两个按钮，并且每一步都先"看一眼"、再"动手"、动完再"检查"，出错能一键撤回。

写代码的心态就一句：**它是一个很笨的助手，你得把每一步写得死板又啰嗦，它才不会犯错。**

## 1. 手工步骤 → 代码，一一对应

这是整份文档最重要的一张表。代码不是凭空来的，每个函数都是在翻译你手上的某个动作。

| 你手工怎么做 | 代码里叫什么 | 一句大白话 |
|---|---|---|
| 看 Fit 里有没有 Spine4、Knee 有没有扭转 | `preview_fit` → `_fit_plan` | 先拿本子记下"缺什么"，**不动手** |
| 在 Spine3 和 Chest 之间插一根骨 | `apply_fit` → `_insert_spine4` | 照着本子，真的去补 |
| 给 Neck 的 inbetweenJoints 填 1 | `apply_fit` 里的 `neck` 分支 | 改一个数字 |
| 点 Build | **工具不做** | 这步你自己点，工具不替你 Build |
| 选中 ADV 和 UE，看它们对不对得上 | `auto_detect`、`resolve_selection` | 自动认出哪棵树是 ADV、哪棵是 UE |
| 心里列"哪根 UE 骨对哪根 ADV 骨" | `deform_mapping` | 一张 79 行的**对照表** |
| 一根根检查：缺不缺、被锁没、有没有别的约束 | `_plan` | 逐对打勾，凡是有问题的就停 |
| 把 UE 骨拖到 ADV 骨的位置并转到对的朝向 | `_match_targets` → `_do_match` → `_write_world` | 先算"应该在哪"，再一根根摆过去 |
| Constraint → Point / Orient / Scale，勾 Maintain Offset | `_create` | 每对骨建 3 个约束 |
| 看看有没有歪、有没有漏 | `apply` 里的复查段 | 动完再核对一遍 |
| 不对就 Ctrl+Z | 撤销块 + 自动回滚 | 整套是一个撤销块，一键全回 |

## 2. 整体长什么样（分三层）

```
┌─────────────────────────────────────────────┐
│ 第 1 层：窗口 show()                         │  ← 你点的按钮都在这
│   补骨 / 检查 / 执行 / 三个勾选框              │
└───────────────┬─────────────────────────────┘
                │ 只负责"问你"和"显示结果"
┌───────────────▼─────────────────────────────┐
│ 第 2 层：两对"先看后做"函数                    │
│   preview_fit  ──►  apply_fit   （Build 前）  │
│   preview      ──►  apply       （Build 后）  │
└───────────────┬─────────────────────────────┘
                │ 每对里：preview 只读，apply 才动场景
┌───────────────▼─────────────────────────────┐
│ 第 3 层：小零件（每个只干一件事）               │
│   _find_adv / _find_ue / _plan / _write_world │
│   _create / _link_state / _stray_bones ...    │
└─────────────────────────────────────────────┘
```

**为什么分成 `preview` 和 `apply` 两个函数？**
就像出门前先看天气预报，再决定带不带伞。`preview` 只看不动，所以你可以随便点"检查"，场景绝对不会变；`apply` 才真的动手。

## 3. 第一步"补骨"的思路

### 3.1 要补什么

| 要补的 | 为什么要补 | 怎么判断 |
|---|---|---|
| Spine4 | UE 有 spine_01~05 五节，ADV 默认少一节 | Fit 里找不到 `Spine4` 就插 |
| Neck 中段 1 根 | UE 只有 `neck_02` 一根颈中间骨 | `inbetweenJoints` 不等于 1 就改成 1 |
| 四肢扭转 | UE 每条肢体有 `twist_01/02` | 没有 `twistJoints` 就加，值为 2 |

### 3.2 `_fit_plan` 的判断套路

Spine4 和四肢扭转是**两选一**：

```
已经有了   →  skip    （跳过，不重复做）
根本没有   →  create  （新建）
```

Neck 多一档，是**三选一**，因为 ADV 默认就带着 `inbetweenJoints=2`，数值不对不能当成"没有"：

```
已经是 1         →  skip   （跳过）
有，但数值不是 1  →  set    （只改数字，不重复新建属性）
根本没有         →  add    （新建属性再填 1）
```

你的场景正好走 `set`：把 2 改成 1。

### 3.3 一个很阴险的坑：路径会失效

`_insert_spine4` 会把 Chest 挂到新的 Spine4 下面。
**Maya 里一个节点的"完整路径"包含它所有父级的名字。** 父级一换，Chest 以及它下面所有骨的路径全变了。

如果代码在插入之前就把路径存起来，插入之后再用，就会报 `No object matches name`。

解决办法：**别存路径，存名字，要用的时候再去查。** 所以 `apply_fit` 里插完 Spine4 后会调用 `_find_fit` 重新扫一遍整棵树。

## 4. 第二步"匹配 + 约束"的思路

### 4.1 先搞清楚两个"骨架"是谁

- **ADV 系统**：`|Group` 下面有 `DeformationSystem`（变形骨）和 `Main`
- **UE 骨架**：一根叫 `root` 的 joint，下面挂着 87 根骨

`_find_adv` 和 `_find_ue` 就是在验证"你给我的这个东西，是不是真的是 ADV / UE"。验不过就明确告诉你缺什么。

### 4.2 对照表 `deform_mapping`

这张表是整个工具的"字典"：左边是 ADV 骨名，右边是 UE 骨名。

```
Root_M      ↔ pelvis
Spine1_M    ↔ spine_01
Shoulder_R  ↔ upperarm_r
ElbowPart1_R↔ lowerarm_twist_02_r    ← 注意！肘部扭转编号是反的
ElbowPart2_R↔ lowerarm_twist_01_r
NeckPart1_M ↔ neck_02
...共 79 行
```

**为什么肘和膝是反序？** 因为 UE 的 Mannequin 里，前臂/小腿的 twist 编号方向跟 ADV 的 Part 编号方向相反。这是我在 ADV 源码里查到的，不是猜的。

### 4.3 `_plan`：出一份"体检报告"

`_plan` 是整个工具最重的函数。它不改场景，只回答一个问题：**"这次能做什么、不能做什么、为什么？"**

它把每一对骨分进不同的格子：

```
两边都有           → pairs         （能连）
UE 有，ADV 没驱动骨 → unavailable   （跳过，并告诉你怎么补）
UE 自己就没这根骨   → skipped       （跳过）
```

**关键设计：缺骨不阻断。** 早期版本只要少一根骨就整个报错，一根都连不上，你的实际场景就卡在这。现在改成"能连多少连多少"。

但有 4 种情况**必须停**，因为继续做会出错或出"看起来对、其实错"的结果：

| 阻断条件 | 为什么必须停 |
|---|---|
| 主骨能配上的不到 40% | 多半是选错了骨架 |
| 有映射表之外的 UE 骨（如 `clavicle_l1`） | 它带着的那条肢体不会被处理，位置会一直错 |
| 目标上已有别的约束 / 动画 / 锁定 | 不覆盖你已有的东西 |
| UE 已经蒙皮 | 工具只用于蒙皮之前 |

### 4.4 匹配的数学（只讲你需要知道的）

**位置**：直接抄 ADV 骨的位置。

**朝向**：

```
UE 的朝向 = 偏移矩阵 × ADV 的朝向
```

"偏移矩阵"就是你之前一遍遍确认的那几条规则：

| 区域 | 偏移 | 含义 |
|---|---|---|
| 脊柱 / 颈 / 头 | (0, 0, 0) | 和 ADV 同向 |
| 手臂 | (0, 180, 0) | 绕 Y 转 180：X 反、Z 反、Y 不变 |
| 手和手指 | (90, 0, 180) | X 反，Y 与 Z 互换 |
| 腿 | (0, 0, 0) | 同向 |

**为什么是"偏移 × ADV"而不是"ADV × 偏移"？** 乘的顺序不同，意思完全不同。
- 偏移 × ADV：不管这根骨朝哪，"ADV 的各个轴"和"UE 的各个轴"之间的换算关系都是固定的
- ADV × 偏移：只在局部坐标里成立，换一根朝向不同的骨就不对了

这个我在 v2.2.1 踩过坑，当时写反了。

**写入的方式 `_write_world`**：把 rotate 清零，朝向放进 jointOrient。
这样 UE 骨的 rotate 通道是干净的，导出到 UE 时不会带奇怪的数值。

### 4.5 建约束 `_create`

```python
pointConstraint(ADV骨, UE骨, maintainOffset=True)
orientConstraint(ADV骨, UE骨, maintainOffset=True)
scaleConstraint(ADV骨, UE骨, maintainOffset=True)
```

**`maintainOffset=True` 是什么？** "建约束的这一刻，两根骨之间差多少就一直差多少。"
因为我们前一步已经把它们摆到完全重合，所以这个偏移几乎为 0。

## 5. 三层安全网（为什么敢放心点）

| 层 | 做了什么 | 大白话 |
|---|---|---|
| 预览只读 | `preview` 开头结尾各拍一张"场景快照"，不一样就报错 | 看的时候不许动 |
| 一个撤销块 | `undoInfo(openChunk=True)` … `closeChunk=True` | 整套操作打包成一步，Ctrl+Z 一次全回 |
| 复查 + 回滚 | 动完核对：UE 骨到没到位、ADV 骨有没有被误动、约束建没建全。任何一项不对，自动撤销 | 干完活自己验收，不合格返工 |

还有两个小细节：
- **确认框默认选"取消"**，误按回车等于什么都没发生。
- **回滚前先看栈顶**：只有栈顶是自己这次的块才撤销，绝不会误撤你之后的操作。

## 6. 我踩过的坑（后来都变成了检查）

每个坑都对应代码里一段现在的防护。

| 坑 | 现象 | 现在的防护 |
|---|---|---|
| **路径失效** | 插完 Spine4 后报 `No object matches name` | 存名字、不存路径，插完重扫 |
| **取了不该取的节点** | `xform` 报错 `No valid objects supplied` | `_tree` 只留 `transform` 和 `joint`，把约束、曲线形状、IK 手柄过滤掉 |
| **撞名残留** | `clavicle_l1` 带着整条左臂，检查却全绿 | `_stray_bones` 检出映射表之外的骨并阻断 |
| **旋转平均** | 想把两个朝向求平均给中间骨，结果矩阵不正交 | 中间骨直接沿用上一根的朝向，只取位置中点 |
| **测错东西** | 转 ADV 变形骨"没反应"，以为驱动失败 | 变形骨本身被 ADV 约束着，**要转 FK 控制器**才对 |

最重要的一条教训是撞名残留那个：

> **只检查"配上的"是不够的，还要检查"没配上的"。**
> 全部通过不代表没问题，要看有没有东西被漏掉。

## 7. 你可以自己改的 4 个地方

都在 `adv_ue_deform_link.py` 文件顶部，改完保存，再拖一次启动器就生效。

| 名字 | 现在的值 | 改它会怎样 |
|---|---|---|
| `ORIENT_OFFSETS` | 各区域的度数 | 改某区域的朝向规则；填 `None` = 这个区域只搬位置、不转朝向 |
| `FIT_NECK_INBETWEEN` | `1` | 颈中间骨的根数 |
| `FIT_TWIST_COUNT` | `2` | 四肢扭转骨几节 |
| `MAIN_COVERAGE_MIN` | `0.4` | 主骨匹配多少比例以下，判定为"选错骨架" |

**抄改练习**：把 `ORIENT_OFFSETS` 里 `"arm_l": (0.0, 180.0, 0.0)` 改成 `None`，保存，再点"检查"，看窗口里"转朝向 N 根"的数字少了多少。这就是左臂那一批骨。改回来就恢复。

## 8. 动手：三段只读小代码

下面三段都**只看不改场景**，可以放心在 Script Editor（Python 标签页）里跑。

### 8.1 看工具认不认得你的场景

```python
import sys
sys.path.insert(0, r"C://path//to//ADV_UE_FitMatcher_v3")  # 改成你自己的目录
import adv_ue_deform_link as m

print(m.auto_detect())
```

逐句看：
- `import sys` / `sys.path.insert(...)`：告诉 Python"去这个文件夹里找工具"。就像告诉快递员地址。
- `import adv_ue_deform_link as m`：把工具请进来，以后简称 `m`。
- `m.auto_detect()`：让它自己扫场景。返回两个列表：找到的 ADV 系统、找到的 UE 根。
- 正常会打印 `(['|Group'], ['|root'])`。

### 8.2 看"体检报告"

```python
r = m.preview("|Group", "|root", match=True, orient=True, link=True)
print(r["status"])
print(r["counts"])
print(r["issues"])
```

逐句看：
- `m.preview(...)`：交一份"体检申请"。三个参数是三个勾选框。
- `r` 是**返回值**，是一个字典（像查电话本：用名字查内容）。
- `r["status"]`：`ready` 能做 / `unchanged` 已经做完了 / `blocked` 被拦住了。
- `r["counts"]`：几对要搬位置、几对要转朝向、几对要连约束。
- `r["issues"]`：被拦的原因，空列表 `[]` 就是没问题。

### 8.3 查一根骨的世界位置

```python
import maya.cmds as cmds
w = cmds.xform("upperarm_l", q=True, ws=True, matrix=True)
print(w[12:15])
```

逐句看：
- `cmds.xform(..., q=True)`：`q` 是 query，只问不改。
- `ws=True`：问的是世界空间的位置。
- `matrix=True`：要一个 16 个数的矩阵。
- `w[12:15]`：矩阵的第 13~15 个数就是 X、Y、Z 位置。

> **黄金技巧**：在 Maya 里手动点一下某个操作，Script Editor 上面那一栏会**回显刚才执行的命令**。
> 抄下来，就是脚本。想学某个 cmds 怎么用，手动点一遍，看回显。

## 9. 函数速查表

| 函数 | 干什么 | 动不动场景 |
|---|---|---|
| `show` | 画窗口 | 否 |
| `preview_fit` / `apply_fit` | Build 前补骨：看 / 做 | 否 / **是** |
| `preview` / `apply` | Build 后匹配+约束：看 / 做 | 否 / **是** |
| `auto_detect` / `auto_detect_fit` | 扫场景找 ADV / UE / Fit | 否 |
| `resolve_selection` | 从你选中的任意节点反推属于哪棵树 | 否 |
| `deform_mapping` | 79 行对照表 | 否 |
| `_plan` | 出体检报告 | 否 |
| `_fit_plan` | 出补骨计划 | 否 |
| `_stray_bones` | 找映射表之外的骨 | 否 |
| `_link_state` | 判断一对骨的约束状态：ok / none / foreign / partial | 否 |
| `_match_targets` | 算每根骨应该摆到哪 | 否 |
| `_do_match` | 把骨摆过去 | **是** |
| `_write_world` | 往一根 joint 写入世界矩阵 | **是** |
| `_create` | 建 3 个约束 | **是** |
| `_find_adv` / `_find_ue` / `_find_fit` | 验证并整理出骨架信息 | 否 |
| `_tree` / `_index` | 列出所有子节点 / 按短名建索引 | 否 |
| `_world` / `_near` | 取世界矩阵 / 判断两个矩阵是否相等 | 否 |

函数名以 `_` 开头的是"内部小零件"，你平时不用直接调用。
